# Phase 2 Signature Verification — Implementation and Test Report

Date: 26 August 2026

## Executive result

The Phase 2 engineering implementation is complete for SignToowix's current signing architecture: participant actions are followed by one final platform CMS/PFX signature.

Local automated verification and the isolated three-signer workflow pass. Production activation is not yet complete because the deployment still needs an approved trust-anchor bundle, an approved RFC 3161 TSA, removal or replacement of the stale PFX_BASE64 secret, and live CA OCSP/CRL interoperability testing. No production deployment was performed.

## Production activation checklist

These actions cannot be completed from the local repository alone:

1. Remove or replace the expired PFX_BASE64 value in every deployment. It currently overrides the valid repository fallback.
2. Configure a production document-signing trust-anchor bundle.
3. Select and contract an approved RFC 3161 timestamp authority.
4. Configure TSA_URL, TSA_TRUST_ANCHORS and the desired TSA_FAIL_CLOSED policy.
5. Test OCSP and CRL against several real production CA certificates and responders.
6. Rebuild and deploy to a non-customer staging environment.
7. Run the full signing, email, download, certificate, QR and verification regression there.
8. Promote only after staging health checks pass.

## Final conclusion

Phase 2 code and deterministic local tests are complete for the current one-platform-signature architecture. It is not accurate to call Phase 2 production-deployed or production-trusted until the external trust roots, TSA, live revocation responders and deployment regression checklist above are completed.
